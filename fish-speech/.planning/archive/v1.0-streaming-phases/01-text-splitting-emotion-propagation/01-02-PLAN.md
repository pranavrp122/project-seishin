<objective>
Wire split_text_into_chunks() into the generate_long() pipeline and add integration tests verifying the end-to-end text-to-batches flow. This replaces the `batches = [text]` fallback for single-speaker text with proper chunked splitting.

Purpose: Without this integration, the splitting function exists but is never called -- the streaming pipeline would still batch everything into one chunk. This is the 3-line change that activates Phase 1's work.
Output: Modified generate_long() + integration tests proving the wiring works.
</objective>

<threat_model>
## Security Considerations

1. **No new attack surface:** This plan modifies the internal control flow of generate_long() but does not change any API surface, input parsing, or output format. The text has already been validated by ServeTTSRequest before reaching generate_long().

2. **Fallback safety:** The empty-list fallback (`if not batches: batches = [text]`) ensures that even if split_text_into_chunks returns [] for unexpected input, the existing behavior is preserved rather than crashing.

Risk: NONE -- purely internal wiring change.
</threat_model>

            """When split_text_by_speaker returns empty, split_text_into_chunks is used."""

            assert len(chunks) >= 2
