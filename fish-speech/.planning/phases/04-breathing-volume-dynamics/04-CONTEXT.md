<decisions>
## Implementation Decisions

### Critical Constraints (from prior phases)
- **D-01:** [inhale] tags are non-responsive — Phase 1 tested all inline tags; only punctuation and [slow] work. Breathing CANNOT be done via text tags.
- **D-02:** Post-FX chain (Phase 2) is disabled — A/B testing showed EQ/compression/saturation degrades audio clarity. Phase 4 must NOT re-enable or depend on HumanismPostFX.
- **D-03:** Breathing sound synthesis is out of scope (anti-feature in REQUIREMENTS.md). Model generates breaths natively from reference audio.

### Breathing Mechanism (BRVL-01, BRVL-02)
- **D-04:** Implement breathing as silence gap insertion (~80-150ms) at BreathingCue positions in audio post-processing. This creates natural breath-length pauses; the model may fill adjacent audio with breath-like characteristics from reference audio patterns.
- **D-05:** BreathingCue metadata already generated by Phase 3 TextPreprocessor (tiered probability: 0.3 for 15-20 words, 0.6 for 20-30, 0.9 for 30+). Phase 4 consumes these cues, applying probability roll at audio insertion time.
- **D-06:** Cap breathing insertion at max 1 per 3-5 sentences as specified (BRVL-02). Count sentences in the text and enforce spacing.

### Volume Dynamics (BRVL-03, BRVL-04)
- **D-07:** [low volume] and [volume up] tags are NOT used — assumed non-responsive like other inline tags. Volume variation is pure audio post-processing.
- **D-08:** Simple numpy gain scaling on audio segments: asides/parentheticals get ~0.85x gain, emphasis/exclamations get ~1.1x gain. No EQ, no compression, no saturation.
- **D-09:** Detect emphasis/aside segments via text analysis (parentheses, em-dashes for asides; exclamation marks, caps, emotion tags for emphasis). Add this detection to HumanismHints as a new VolumeHint field.
- **D-10:** Gain transitions use short cosine ramps (~20ms) to avoid clicks/pops at volume change boundaries.

### Architecture
- **D-11:** New lightweight class `HumanismAudioProcessor` in `fish_speech/utils/audio_processor.py`. Separate from post_fx.py (which is disabled). Takes (audio_segment, HumanismHints, sample_rate) and returns processed audio.
- **D-12:** Integrate into inference engine's streaming loop where post_fx.process() was called (same 3 audio paths: sub-chunk partial, sub-chunk final, non-sub-chunk). Replace the `post_fx is not None` guards with audio_processor calls.
- **D-13:** HumanismHints must flow from the preprocessor (currently local variable) to the audio processing stage. Store on the inference request or pass through the streaming loop.

### Audio Position Mapping
- **D-14:** Text char_offsets in HumanismHints don't map directly to audio sample positions (variable-length generation). Use approximate mapping: divide total audio duration proportionally by text length. Exact positioning not critical — breathing pauses and volume shifts are perceptual, not sample-accurate.

### Claude's Discretion
- Exact silence duration for breathing gaps (80-150ms range)
- Gain multiplier values for aside/emphasis (guideline: 0.85x/1.1x)
- Cosine ramp duration for gain transitions
- Whether VolumeHint is a new dataclass or extends existing HumanismHints
- Integration approach for passing humanism_hints through the streaming loop

</decisions>
